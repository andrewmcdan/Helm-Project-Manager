Help

How Helm works today: account access, day-to-day workflows, and administrator tools.

This guide is aligned with the current screens, routes, and available actions in the app.

What Helm Is

Helm is a single shared project workspace for tracking requirements, effort, risks, team members, and project settings.

Project model

One shared project

Core work areas

Requirements, Effort, Risks

Access

Signed-in users

Account Access

Register a new account From Login

Use the New User button on the login page, complete your profile details, choose a role, and set three security questions. New accounts stay pending until an administrator approves them.

Sign in with your username Not email

Helm sign-in uses username plus password. Your generated username is included in the approval email after an administrator activates your account.

Reset a forgotten password Email + username

Use Forgot Password, enter your email and username, then follow the emailed reset link. The reset form asks for your three security answers before you set a new password.

Password rules Security

Passwords must be at least 8 characters and include an uppercase letter, lowercase letter, number, and special character.

Temporary passwords and lockouts Admin support

Administrator-created or administrator-reset accounts may receive a temporary password by email. Three failed sign-in attempts or an expired password can leave the account suspended until an administrator reinstates it.

Typical Flow

1. Create or review requirements Requirements

Add the requirement, assign its type, priority, status, and tags, then keep the details current as work moves forward.

2. Log effort against active work Effort

Log hours from the Effort page or jump there directly from a requirement so the correct requirement is already selected.

3. Maintain the risk register Risks

Capture new risks, update impact or likelihood, record mitigation plans, and add update notes as the project changes.

4. Review people and project setup Admin tasks

Use Team for roster management and Project Settings for shared project details. Use Dashboard when you need the full account-administration toolset.

Requirements

The requirements area is the main planning surface for functional and non-functional work.

Create requirement Modal form

The create form collects title, requirement code or code prefix, description, type, priority, status, and comma-separated tags. You can create one item or create and immediately add another.

Search, filter, and export Backlog tools

Search by title or identifier, filter by type, status, and priority, change how many rows are shown, and export the current requirements list to CSV.

Inline detail editing Details panel

Each requirement can be edited in the details card on the right. Current editing covers title, description, status, priority, type, and tags.

Effort and archive actions Per row

Use Details to load the item, Effort to jump to logging, and Archive to remove it from active lists and effort dropdowns.

Acceptance criteria display Read-only summary

The details card currently shows how many acceptance-criteria items exist for the requirement, but those items are not edited directly from this page.

Effort

Use Effort to save time entries and review totals across the project.

Daily or weekly entries Two modes

The form supports Daily and Weekly entries. Every entry requires a requirement, a category, and a positive number of hours. Notes are optional.

Context from requirements Fast path

When you jump to Effort from a requirement, Helm carries the requirement into the effort form and shows a banner so you know which item you are logging against.

Overview filters Review totals

The overview supports All time, This week, Last week, and This month, plus user and category filters. Results are shown as totals by requirement and totals by category.

Recent entries Cleanup

The recent-entry table shows the newest effort records and supports deleting entries that should not stay in the log.

Built-in categories Reporting

Current categories are Requirements Analysis, Design, Coding, Testing, and Project Management.

Risks

The risk register tracks active concerns, ownership, mitigation, and update notes.

Create risk Modal form

A new risk includes risk code, title, description, likelihood, impact, status, optional owner, and mitigation plan.

Statuses and levels Current values

Risk status values are Identified, Analyzed, Mitigated, and Closed. Likelihood and impact values are Low, Medium, High, and Critical.

Details and mitigation Inline editing

The details panel edits title, description, status, likelihood, impact, and owner. The mitigation panel stores the mitigation plan separately so it can be updated without changing the rest of the record.

Update notes and history Timeline

Use Add update to record a note and update type. Use View history to review the recent update log for that risk.

Filter, archive, export Register tools

Filter by search, status, likelihood, or impact, archive items that should leave the active register, and export the register to CSV.

Team

Team focuses on the roster, member lookup, and administrator actions.

Directory and filters Search

Search by name or email, filter by role and status, and open any member into the details card.

Administrator actions Team page

Administrators can add members, change a member role, approve or reject pending members, suspend active members, reinstate suspended members, and export the roster.

Role list Available roles

Current roles are Administrator, Manager, Coder, and Viewer. Administrator-only actions are enforced for account management and project settings.

Dashboard Admin Tools

The Dashboard contains the deeper user-management workflows that are not all surfaced on Team.

Approvals and reinstatement Administrator

Approve or reject new accounts, review suspended users, and reinstate them directly from the dashboard.

Full account administration Administrator

Create users, edit user fields in the account table, suspend accounts with dates, reset passwords, delete users, and send direct emails.

Project snapshot All signed-in users

Outside the administrator section, Dashboard is primarily a project snapshot page rather than the main place for day-to-day work entry.

Project Settings

Project Settings stores the shared project record used across Helm.

Administrator-only edits Protected

Only administrators can save project changes. Non-admins can still open the page and review the current values.

Shared fields Project record

The editable project record includes project name, owner or PM name, description, contact email, project status, and stored effort defaults.

Change log History

Every saved settings change is added to the change log so administrators can review what changed and who changed it.

Profile and Security

Profile controls your own account details.

Personal information Profile

Update your first name, last name, email, address, and profile image from the profile form.

Change password Current password required

The password form requires your current password, then validates the new password against Helm's complexity rules.

Security questions Three required

Profile lets you replace all three security questions and answers, but the update requires your current password.

Troubleshooting

Cannot sign in Authentication

Use your username, not your email address. If you just registered, wait for administrator approval. If you have failed sign-in several times, your account may need administrator reinstatement.

Password reset is not working Recovery

The reset request needs both your email and username. The reset link then requires the correct answers to all three of your security questions.

Requirement is missing from Effort Effort

Effort only lists active requirements. Archived requirements do not appear in the requirement dropdown.

Cannot change Team or Project Settings Permissions

Administrator-only actions are enforced for project settings changes and most user-management actions.

Password expired Administrator needed

Expired passwords can suspend the account. Contact an administrator to reset or reinstate access if you can no longer sign in.
